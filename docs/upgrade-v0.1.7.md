# Обновление до v0.1.7 и повторный импорт из dhcpd

© 2026 Кислов Роман Сергеевич. Apache License 2.0. Редакция 30 октября 2026.

Инструкция для уже работающего GoDHCP с SQLite и пакетной службой systemd. Команды выполняйте в root-сессии Bash (`sudo -i`) в согласованное окно обслуживания. Существующие клиенты сохраняют полученные адреса до истечения своих аренд; во время остановки сервера новые выдачи и продления недоступны.

**База аренд остаётся прежней. Импорт выполняется в отдельный YAML, из которого вручную переносятся только нужные настройки. Импортированный файл не заменяет рабочую конфигурацию целиком.**

Если DHCP пока обслуживает ISC dhcpd, эта инструкция не заменяет план миграции: GoDHCP не импортирует состояние из `dhcpd.leases`. Занятые адреса ISC должны быть защищены от повторной выдачи отдельно.

## 1. Проверьте версию и действующие пути

```bash
godhcp version
systemctl cat godhcp
less /etc/godhcp/config.yml
```

Далее предполагаются бинарник `/usr/bin/godhcp`, конфиг `/etc/godhcp/config.yml`, секреты `/etc/godhcp/godhcp.env`, база `/var/lib/godhcp/leases.db`. Проверьте путь запуска в unit и значение `database.dsn`. Если пути отличаются, замените их во всех командах, включая резервное копирование. Для PostgreSQL нужна резервная копия средствами PostgreSQL; команды копирования SQLite к нему не применяются.

Не публикуйте конфиг и env-файл: они могут содержать пароли, JWT и API-ключи. Экспорт из веб-интерфейса маскирует часть секретов и не заменяет резервную копию файлов сервера.

## 2. Скачайте пакет и проверьте SHA-256

Скачайте из [релиза v0.1.7](https://github.com/rkislov/gdhcp/releases/tag/v0.1.7) файл `SHA256SUMS` и один пакет своей системы в отдельный каталог. Проверьте архитектуру:

```bash
uname -m
```

Следующие пакеты предназначены для `x86_64`:

- ALT Linux p10: `godhcp-0.1.7-alt1.p10.x86_64.rpm`.
- Astra Linux: `godhcp_0.1.7-1astra_amd64.deb`.
- РЕД ОС: `godhcp-0.1.7-1.redos.x86_64.rpm`.

В каталоге скачивания выполните только одну подходящую проверку:

```bash
# ALT Linux p10:
grep '  godhcp-0.1.7-alt1.p10.x86_64.rpm$' SHA256SUMS \
  | sha256sum -c -

# Astra Linux:
grep '  godhcp_0.1.7-1astra_amd64.deb$' SHA256SUMS \
  | sha256sum -c -

# РЕД ОС:
grep '  godhcp-0.1.7-1.redos.x86_64.rpm$' SHA256SUMS \
  | sha256sum -c -
```

Продолжайте только при результате `OK`. SHA-256 проверяет целостность; пакеты не подписаны ключом репозитория. RPM для РЕД ОС проверен на Rocky Linux 9, а не на самой РЕД ОС: официальный реестр не прошёл проверку TLS-сертификата.

## 3. Остановите службу и сохраните настройки и аренды

На время работ прекратите изменения через веб-интерфейс. Сначала остановите службу:

```bash
systemctl stop godhcp
systemctl is-active godhcp
```

Ожидается `inactive`; команда проверки при этом возвращает ненулевой код. Если служба остаётся активной, не переходите к копированию базы: выясните причину. Дальнейшие команды выполняйте вручную, а не единым скриптом с `set -e`.

В той же root-сессии Bash создайте резервную копию:

```bash
umask 077
backup_dir="/root/godhcp-backup-$(date +%Y%m%d-%H%M%S)"
install -d -m 0700 "$backup_dir"

cp -a /etc/godhcp "$backup_dir/etc-godhcp"
cp -a /var/lib/godhcp "$backup_dir/var-lib-godhcp"
cp -a /usr/bin/godhcp "$backup_dir/godhcp.previous"
systemctl cat godhcp > "$backup_dir/godhcp.service.txt"
printf 'Резервная копия: %s\n' "$backup_dir"
```

Запишите выведенный путь: переменная `backup_dir` не сохраняется после закрытия сессии. Если база расположена вне `/var/lib/godhcp`, скопируйте после остановки и её каталог с сохранением прав.

Копируется весь каталог базы вместе с возможными `leases.db-wal` и `leases.db-shm`. Не удаляйте их отдельно и не копируйте один `leases.db` во время работы сервера. Сохраните также внешние сертификаты и секреты, расположенные вне `/etc/godhcp`, если используете их.

Если установлен `sqlite3`, проверьте копию:

```bash
sqlite3 "$backup_dir/var-lib-godhcp/leases.db" \
  'PRAGMA integrity_check;'
```

Ожидается `ok`. При ошибке не продолжайте обновление до выяснения причины. Храните резервную копию с ограниченным доступом.

## 4. Установите обновление

В каталоге скачанного пакета выполните одну команду своей системы:

```bash
# ALT Linux p10:
apt-get install ./godhcp-0.1.7-alt1.p10.x86_64.rpm

# Astra Linux:
apt install ./godhcp_0.1.7-1astra_amd64.deb

# РЕД ОС:
dnf install ./godhcp-0.1.7-1.redos.x86_64.rpm
```

Затем проверьте версию:

```bash
systemctl daemon-reload
/usr/bin/godhcp version
```

Должно отобразиться `godhcp 0.1.7`. Не копируйте `config.yml.example` поверх рабочего конфига, не создавайте новую базу и не удаляйте старую. Пакеты не запускают службу автоматически. При обновлении вручную установленного бинарника сохраните прежний unit и пути запуска; сначала проверьте, что новый пакет не конфликтует с вашей схемой установки.

## 5. Повторите импорт в отдельный файл

Исходный `dhcpd.conf` и все файлы из директив `include` должны быть доступны по указанным путям. Относительные пути разрешаются от файла, содержащего include. Следующая команда перезаписывает только указанные файлы результата и журнала, если они уже существуют:

```bash
umask 077
/usr/bin/godhcp import-dhcpd \
  -in /etc/dhcp/dhcpd.conf \
  -out /etc/godhcp/imported-v017.yml \
  2> /etc/godhcp/imported-v017.log
```

Проверьте, что команда завершилась без ошибки, затем прочитайте журнал и YAML:

```bash
cat /etc/godhcp/imported-v017.log
less /etc/godhcp/imported-v017.yml
```

Импорт не запускает DHCP, не меняет исходный `dhcpd.conf` и не записывает аренды в базу. В версии 0.1.7 исправлена потеря `shared-network` после неподдерживаемого блока `class`. Для примера VLAN116 должны сохраниться подсеть `10.0.116.0/22` и фиксированные адреса, включая `SRV-ZABBIX` с `10.0.116.10`, если они есть в исходнике.

Предупреждение о пропуске `class` ожидаемо. Условия классов не переносятся автоматически: выбор подсети по relay (`giaddr` или Option 82) необходимо проверить вручную. Директива `authothriative` в исходнике содержит опечатку; правильное написание `authoritative`, но менять режим без проверки роли сервера не следует.

## 6. Перенесите недостающие резервации в копию рабочего конфига

```bash
cp -a /etc/godhcp/config.yml /etc/godhcp/config.next.yml
```

Откройте `config.next.yml` в доступном текстовом редакторе. Из `imported-v017.yml` перенесите нужные записи `reservations` в соответствующие существующие подсети. Пример фрагмента внутри подсети:

```yaml
    reservations:
      - mac: "78:e3:b5:14:dc:7c"
        ip: 10.0.116.10
        hostname: SRV-ZABBIX
```

Если список `reservations` уже есть, добавьте элементы в него; не создавайте второй одноимённый ключ. Соблюдайте отступы YAML и не используйте табуляцию. Сверьте число и адреса резерваций с исходными `host`/`fixed-address`, проверьте дубликаты MAC/IP и конфликты с действующими арендами других клиентов. При конфликте согласуйте перенос клиента; не удаляйте активную аренду для принудительной выдачи занятого адреса.

Сохраните текущие `database.driver`, `database.dsn`, идентификаторы подсетей `id`, диапазоны, интерфейсы, VLAN, relay, параметры API, пользователей, TLS и секреты. Новые идентификаторы из импорта не должны заменять существующие: с ними связаны текущие аренды. Если подсеть ранее отсутствовала, отдельно перенесите и проверьте её параметры и выбор через relay.

Импортированный файл не является полной копией настроенного GoDHCP: в частности, в нём не восстановлены ваши пользователи и политики доступа. Применение всего результата импорта поверх рабочего конфига может изменить доступ к управлению.

## 7. Проверьте кандидат и запустите сервер

Для пакетной службы следующая команда проверяет конфиг от пользователя `godhcp`, загружая секреты из того же env-файла, что использует служба:

```bash
systemd-run --unit=godhcp-validate-v017 --wait --pipe \
  -p User=godhcp \
  -p Group=godhcp \
  -p EnvironmentFile=/etc/godhcp/godhcp.env \
  /usr/bin/godhcp -validate \
  -config /etc/godhcp/config.next.yml
```

Ожидается `configuration is valid` и успешное завершение команды. При ошибке рабочий файл не меняйте. Проверьте права чтения конфига для `godhcp`, наличие env-файла и значения переменных; обычная shell-команда сама `godhcp.env` не загружает. При повторном запуске после неудачной проверки можно использовать новое имя unit, например `godhcp-validate-v017-retry`.

После успешной проверки:

```bash
cp -a /etc/godhcp/config.next.yml /etc/godhcp/config.yml
systemctl start godhcp
systemctl status godhcp --no-pager
journalctl -u godhcp -n 100 --no-pager
```

Если запуск не удался, не повторяйте его многократно: прочитайте ошибку и используйте копию конфигурации для отката. DHCPv4 использует стандартный UDP 67; порт должен быть свободен, а процессу нужны соответствующие привилегии. При `address already in use` выполните `ss -lunp` и выясните владельца порта, прежде чем останавливать другой DHCP-сервер. Существующий адрес API и TLS сохраняются; порт 8181 относится к новым примерам конфигурации, а не к обязательной смене вашего порта.

## 8. Проверьте результат в веб-интерфейсе

Откройте прежний URL сервера и войдите с прежней учётной записью. Если вход перестал работать, проверьте, не заменили ли вы настройки `api.auth` импортированными значениями.

- В разделе «Аренды» найдите несколько ранее работавших клиентов: их IP и активные аренды должны остаться.
- В разделе «Резервации» найдите добавленные MAC и проверьте IP и подсеть.
- На одном согласованном тестовом устройстве обновите DHCP-адрес и проверьте получение зарезервированного IP.
- В разделе «Журнал» проверьте отсутствие ошибок базы, выбора подсети и отправки ответов.

Не перезапускайте все клиентские устройства одновременно. Сохраните резервную копию и журнал импорта до завершения проверки. Скриншоты разделов панели приведены в [иллюстрированном руководстве](web-guide.md).

## 9. Откат при проблеме

Остановите службу. Восстановите конфиг из записанного каталога резервной копии; если сессия была закрыта, сначала задайте `backup_dir` фактическим путём вашей копии.

```bash
systemctl stop godhcp
cp -a "$backup_dir/etc-godhcp/config.yml" \
  /etc/godhcp/config.yml
```

Если меняли env-файл или unit, восстановите и их. Для отката версии предпочтительно установить сохранённый предыдущий пакет. Затем проверьте конфигурацию и запустите службу. Отдельная копия прежнего бинарника `godhcp.previous` сохранена для аварийного восстановления; ручная замена файла требует согласования с установленным пакетом.

**Текущую базу аренд сохраняйте.** После запуска v0.1.7 могли появиться новые аренды. Восстановление старой копии базы не делает эти адреса свободными и может привести к повторной выдаче. Восстановление базы выполняйте только отдельной процедурой с учётом всех выдач после снимка; не смешивайте старые и новые WAL/SHM-файлы.
