# DHCPv6 в GoDHCP

© 2026 Кислов Роман Сергеевич. Apache License 2.0.

Поддержка доступна в релизе v0.1.11 и новее. DHCPv6 по умолчанию выключен. Он может работать вместе с DHCPv4 или самостоятельно. Для режима только IPv6 задайте `server.listen: "-"` и оставьте `server.raw_vlan` выключенным.

## Настройка

Глобальный администратор может сохранить следующий раздел через YAML-редактор **Конфигурация** или отредактировать `/etc/godhcp/config.yml`. Замените интерфейс, адреса и DNS значениями вашей сети. Пул должен содержать свободные адреса, выделенные этому DHCP-серверу.

```yaml
dhcpv6:
  enabled: true
  listen: "[::]:547"
  preferred_seconds: 3600
  valid_seconds: 7200
  dns: ["2001:db8:42::53"]
  pools:
    - interface: enp1s0.42
      prefix: 2001:db8:42::/64
      start: 2001:db8:42::100
      end: 2001:db8:42::1ff
```

Создайте и поднимите IPv6-интерфейс ОС до запуска службы. На интерфейсе прямых клиентов необходим link-local адрес. GoDHCP вступает в multicast-группу `ff02::1:2` и выбирает прямой пул по интерфейсу получения пакета. Для одного интерфейса можно задать один прямой пул. Разрешите UDP 547 к серверу и UDP 546 к клиенту. Маршрут по умолчанию клиент получает через Router Advertisement от маршрутизатора. Для сети с управляемыми адресами включите в RA флаг M с учётом требований клиентов.

Параметры `preferred_seconds` и `valid_seconds` по умолчанию равны половине действительного срока и 7200 секундам соответственно. Продление T1 начинается по истечении половины предпочтительного срока, переход к Rebind T2 — по истечении четырёх пятых. После изменения любого параметра `dhcpv6` перезапустите службу.

```sh
sudo -u godhcp godhcp -validate -config /etc/godhcp/config.yml
sudo systemctl restart godhcp
sudo journalctl -u godhcp -g dhcpv6 -n 30
```

## Relay

Для удалённой сети укажите в пуле входной интерфейс **самого сервера**, префикс клиентской сети и список разрешённых IPv6-адресов relay. Например, к списку `pools` можно добавить следующий элемент.

```yaml
    - interface: enp2s0
      prefix: 2001:db8:52::/64
      start: 2001:db8:52::100
      end: 2001:db8:52::1ff
      relays: ["2001:db8:ff::2"]
```

Настройте один relay на передачу Relay-forward на unicast-адрес сервера. Адрес источника должен находиться в списке `relays`, а поле `link-address` — в префиксе клиентского пула. Ответ идёт этому relay на UDP 547 и сохраняет его `Interface-ID`. Сервис поддерживает один переход. Вложенные relay и выбор пула только по Interface-ID при нулевом link-address в этой реализации отсутствуют.

## Аренды и диагностика

GoDHCP выдаёт один адрес на IA_NA. Клиент идентифицируется по DUID и IAID в пределах префикса. Предложение удерживается 60 секунд. Request, Renew и Rebind подтверждаются после записи в SQLite или PostgreSQL. Release освобождает адрес, Decline помещает его в карантин на час. Истёкший адрес можно использовать снова при следующем распределении. Information-request позволяет получить DNS-серверы без выдачи адреса.

При первом включении GoDHCP генерирует DUID-UUID и сохраняет его в таблице `dhcp6_identity`. Для явного задания идентификатора используйте `dhcpv6.server_duid` в hex, с двоеточиями или без них. Сохраняйте базу аренд и конфигурацию при переносе службы.

Для просмотра аренд используйте таблицу `dhcp6_leases` в базе и журнал `dhcpv6 lease`. Пример для SQLite, где путь к файлу соответствует вашему `database.dsn`.

```sql
SELECT ip, prefix, client AS duid, iaid, state,
       datetime(expires, 'unixepoch') AS expires_utc
FROM dhcp6_leases
WHERE expires > unixepoch()
ORDER BY expires;
```

Веб-список аренд и Samba DDNS A/PTR продолжают обслуживать IPv4. Делегирование префиксов IA_PD и регистрация AAAA для клиентов DHCPv6 в эту реализацию не входят. На запрос IA_PD сервер сообщает NoPrefixAvail. Протокол описан в [RFC 9915](https://www.rfc-editor.org/rfc/rfc9915.html).

## Сетевой тест

Из корня проекта запустите `make test-dhcpv6-docker`. Стенд поднимает пару интерфейсов в изолированном Linux-контейнере и проверяет получение адреса с ISC dhclient, обмен multicast-пакетами, DNS, продление после перезапуска, освобождение и один DHCPv6 relay.
