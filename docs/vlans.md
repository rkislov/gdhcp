# VLAN

Локальный клиент. Ядро снимает тег 802.1Q, процесс видит интерфейс `eth0.10` или `vlan10`. Сервер находит VLAN 10, подсеть из `subnet_ref` и выдаёт адрес из её пула. В описании ответа остаётся PCP (`vlans[].priority`), чтобы кадр можно было отправить с 802.1p. Для VoIP в примере это 6.

Режим порта задаётся в `server.interfaces`: `access` (одно поле `vlan`) или `trunk` (список `vlans`). Это описание для оператора и для `manage_links`. Сопоставление запроса идёт по интерфейсу, с которого пришёл датаграмм, и по идентификатору VLAN.

Неизвестный VLAN:

- `ignore` — пакет молча отбрасывается;
- `nak` — NAK, если сервер authoritative;
- `default-pool` — адрес из `relay.default_pool`.

Опции VLAN (`options`) дописываются в ответ. Ключ — номер опции DHCP. Строка `66: tftp.voip.local` становится TFTP server name. Опция 43 уходит как есть и подходит для IP-телефонов и точек доступа.

QinQ (TPID `0x88a8`, затем `0x8100`) собирается функцией кадра и покрыт модульным тестом. Отдельный listener двойной метки в этой версии не поднят.

На Linux `POST /api/v1/vlans` при `server.manage_links: true` вызывает netlink и создаёт подынтерфейс без перезапуска процесса. Удаление записи из конфигурации интерфейс само не сносит: для этого есть `vlan.Delete`.
