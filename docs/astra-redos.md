# GoDHCP 0.1.8: Astra Linux и РЕД ОС

© 2026 Кислов Роман Сергеевич. Apache License 2.0.

Пакеты для x86_64/amd64 используют неизменённый статический бинарник из тега v0.1.8. Веб-интерфейс уже встроен; Node.js не нужен. PDF со скриншотами включён в пакет.

## Скачивание и установка

Файлы сборки находятся в `dist/astra-redos/0.1.8/`. Перед установкой проверьте архитектуру (`uname -m`, ожидается x86_64) и SHA-256 своего файла:

```sh
# Выполняйте из каталога с пакетом и SHA256SUMS.
# Astra Linux:
grep '  godhcp_0.1.8-1astra_amd64.deb$' SHA256SUMS | sha256sum -c -
sudo apt install ./godhcp_0.1.8-1astra_amd64.deb

# РЕД ОС:
grep '  godhcp-0.1.8-1.redos.x86_64.rpm$' SHA256SUMS | sha256sum -c -
sudo dnf install ./godhcp-0.1.8-1.redos.x86_64.rpm
```

Продолжайте установку только после результата OK. Пакеты не подписаны ключом репозитория; SHA-256 проверяет целостность, но не заменяет подпись доверенного издателя.

## Настройка после установки

Установщик создаёт пользователя `godhcp` и каталоги, но не включает службу автоматически. Подготовьте рабочий конфиг и секреты по [руководству администратора](admin-guide.md). Пример находится в `/etc/godhcp/config.yml.example`, рабочие настройки — `/etc/godhcp/config.yml`, переменные службы — `/etc/godhcp/godhcp.env`.

В пакетном примере DHCP отключён через `server.listen: "-"`. Для согласованного запуска выдачи адресов используется UDP `:67`; API в новом примере слушает `127.0.0.1:8181`. Не запускайте второй независимый DHCP в действующем сегменте без согласованного переключения.

```sh
sudo /usr/bin/godhcp -validate -config /etc/godhcp/config.yml
sudo systemctl enable --now godhcp
sudo systemctl status godhcp
```

При ручной проверке конфигурации передайте необходимые переменные окружения из godhcp.env: systemd загружает этот файл для службы, но обычная shell-команда сама его не читает. Подробная безопасная процедура описана в руководстве администратора.

Инструкция по панели установлена в `/usr/share/doc/godhcp/godhcp-web-guide.pdf`. Минимальные контейнерные образы Astra исключают документацию через dpkg path-exclude; в тестах добавлено адресное path-include только для документации GoDHCP. На системе с такой же политикой файл может не устанавливаться, хотя присутствует внутри DEB.

## Что проверено

- Astra Linux UBI 1.7.5 и 1.8.6, amd64: установка с зависимостями, версия бинарника, наличие PDF, `systemd-analyze verify`, переустановка, удаление и сохранение рабочей конфигурации/данных.
- RPM: установка с зависимостями, `rpm -V`, версия, PDF, проверка unit-файла, переустановка и удаление на Rocky Linux 9. Это проверка RPM-окружения, **не проверка РЕД ОС**.
- Установленные бинарники всех трёх тестов побайтово совпадают с бинарником тега v0.1.8; встроенная VCS-ревизия совпадает с коммитом тега, `vcs.modified=false`.
- Нативная проверка РЕД ОС не проведена: официальный реестр `registry.red-soft.ru` вернул ошибку проверки цепочки TLS-сертификата. Проверка TLS не отключалась. Совместимость с конкретными редакциями/обновлениями РЕД ОС 7.3/8 не подтверждена.
- Полноценная загрузка systemd, фактическая выдача DHCP, политики PARSEC/SELinux и работа на сертифицированных установках в этих контейнерных проверках не испытывались. Пакеты не заявляются сертифицированными дистрибутивами. Известные ограничения производительности relay сохраняются, см. [отчёт](performance.md).

## Воспроизведение упаковки

Нужны Git, Go (для чтения buildinfo), Python 3, ripgrep и nFPM; проверен nFPM v2.43.4. Положите проверенный бинарник из релиза v0.1.8 в `dist/releases/0.1.8/godhcp_0.1.8_linux_amd64`, затем выполните:

```sh
bash scripts/build-astra-redos.sh
```

Скрипт извлекает конфиги, unit, документацию и лицензии через git archive из тега, проверяет VCS-ревизию бинарника и формирует DEB/RPM и SHA256SUMS. Дополнительный PDF общего руководства из неотслеживаемого output/ в пакеты не включается; используется документация из тега. Сгенерированные рецепты nFPM сохранены рядом с пакетами для аудита.

Контейнерная проверка использует `scripts/test-astra-redos-container.sh`, формат (`deb`/`rpm`) и абсолютный путь пакета. Передайте TARGET_NAME для имени копии проверенного бинарника и смонтируйте каталог пакетов в /packages с правом записи. Изменение настроек dpkg в тесте выполняется только внутри одноразового контейнера.

Официальные справочники: [образы Astra Linux](https://registry.astralinux.ru/descriptions/local/containers/), [установка RPM в РЕД ОС](https://redos.red-soft.ru/base/faq/faq-rpm-dnf/).
